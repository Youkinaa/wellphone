# V2 验证计划：副屏隔离、通用 Agent 与三个真实 App

日期：2026-09-21。**已完成原生控件/合成 IME 的副屏并发机制子实验；完整 G0–G6 仍未通过。** [实测报告](2026-09-21-appium-concurrency-probe.md)记录 60 秒并发、版本、两个配置失败及未验收项。当前交付范围是单 Android 模拟器实例，真机可选；三个业务均通过 GUI，不以业务 API 或系统数据写入替代。

## 1. 验证顺序与门槛

先证明副屏隔离和真实 App 兼容，再实现完整编排。单独跑通主屏脚本或模型输出，不等于这个项目成立。

**当前优先级：**用户已决定暂缓美团专项崩溃/ANR 排查，先验证腾讯会议的必要页面并打通查询/预约闭环，Web 输入与任务展示并行推进，再扩展截图转日历和美团。下文是各能力启用时的验收条件，不要求先修好美团才能开发其他能力。偶发失败使用[有限重试契约](../superpowers/specs/2026-09-21-agent-runtime-contracts.md#41-mvp-的有限重试)，额度耗尽、未决提交或设备离线仍须暂停/报告。

**交互设计基线：**[交互应用设计](../superpowers/specs/2026-09-21-interaction-app-design.md)采用 Web 上传原图 → VLM 提取 → 副屏日历 GUI 的默认入口；手机图库读图转为独立可选场景。下文据此更新资料入口，G1/G2 隔离、中文及真实业务结果标准不变。交互层可按设计独立开发，真实执行仍受设备门槛约束。

### 1.1 先做无 LLM 的可行性预检

预检仅需要一个 API 34 AVD、固定版本 scrcpy/Appium UiAutomator2、目标 App，以及检查显示/输入的最小适配器或探针。不依赖 LangGraph、Redis、规划器、skills 或模型调用；不能把完整业务开发当成验证 App 的前提。镜像修订号在准备时固定，API 35 不作为第一轮并行适配目标。

| 阶段 | 低成本做法 | 此阶段能够判定 |
| --- | --- | --- |
| P0 文档与静态检查 | 核对镜像 API/ABI、APK 版本和 manifest；阅读系统多屏启动与焦点规则 | 已知平台约束、安装不兼容；manifest 不能独自证明全部页面留副屏 |
| P1 App 页面预检 | 在专用测试 AVD 预先登录；原版 scrcpy 建副屏，人工走必要页面并记录 task/display | App 能否安装、启动、导航、显示目标字段；此阶段不宣称无干扰 |
| P2 焦点与中文探针 | 应用 scrcpy 禁抢 top focus 与 Appium 范围/Toast/文本补丁；通过复用驱动重复执行观察、SET_TEXT、定向点击/返回；主屏持续软键盘中文组合输入 | 主屏焦点、IME 连接与字符投递保持；副屏文本正确写入。无需模型选择动作 |
| P3 真实必要路径复验 | 用同一底座走日历、会议表单、外卖搜索→规格→结算；覆盖必要保存与提交后页面；图库另列可选项 | 具体 App/页面在目标版本下的兼容矩阵；未运行的支付路径仍属未验证 |

P1 使用原版 scrcpy 的目的只是快速排查页面兼容。原版抢焦点是已知候选缺口，不能据此否定 P2 的修改方案，也不能把 P1 成功当作 P2 通过。手动切换宿主机窗口不作为并发输入证据；P2 由探针操作副屏，避免人为切宿主焦点。

页面预检必须包含冷启动、已存在后台 task、返回与外部 Activity 跳转；不能只打开首页看一次。主屏有目标包旧 task 时先识别并记录，不用 force-stop 或任务迁移掩盖问题。账号登录和权限设置可在准备阶段完成；任务中重新登录、验证或支付需要另外覆盖。

P1 命令模板如下（`SERIAL`、`PACKAGE` 和 `base.apk` 须换成已核验对象；本轮未执行）：

```sh
adb -s SERIAL shell pm list features
scrcpy --serial SERIAL --new-display=1080x1920/420 --start-app=PACKAGE --no-audio --no-clipboard-autosync
adb -s SERIAL shell dumpsys display
adb -s SERIAL shell dumpsys activity activities
adb -s SERIAL shell dumpsys window
apkanalyzer manifest print base.apk
```

检查 `android.software.activities_on_secondary_displays`；实际 display ID 从日志/状态读取，不假定为 1。`--start-app` 不加会 force-stop 的 `+`，也不使用会迁移内容到主屏的 `--no-vd-destroy-content`。`--no-audio` 仅关闭音频转发，不代表关闭 App 的声音或通知；这些仍需单独观察。APK 如包含 splits，静态检查须覆盖实际安装集合。启动许可检查与最终执行使用一致的调用身份，不能把 shell 成功当作普通 APK 权限已成立。

真实创建/提交按具体测试授权执行。外卖可以先走到最终结算页定位界面问题，但未发生的订单提交、扣款和支付回跳不能标为通过。矩阵最少记录镜像、包名/版本、页面/转移、task/display、主屏焦点/IME、中文结果、结论及证据引用。

环境就绪后先设一个工作日的预检投入窗口，在半天与一天时检查证据；这是控制投入的检查点，不是承诺一天解决所有兼容问题。P2 失败时先定位镜像/flag/控件层，不开始 Agent 内核；只有个别 App 的 P3 失败则单独标阻碍并重新判断该演示范围。不得未经说明换成业务 API 或另一台逻辑设备。

环境已推进：本地缓存安装了 SDK、Emulator、JDK 与 Appium，启动一个 API 34 AVD，构建 scrcpy 禁抢焦点补丁和原生夹具，完成 P2 的合成输入机制子实验。P1/P3 的真实 App 页面、P2 的真人拼音及生产隔离边界仍待验证；不能以此更新降低下方 G1/G2/G3 条件。实际镜像与产物版本以实测报告为准。

真实 App 准备进一步发现原 AOSP 镜像不兼容官网 ARM64 包；现已在含 ARM64 翻译的 Google APIs API 34 r14 镜像安装美团和腾讯会议，用户已确认两者登录成功。更换镜像后独立复跑机制探针，完成 87 轮副屏并发操作；安装、机制、性能排查与尚未覆盖的业务边界见[准备报告](2026-09-21-real-app-preparation.md)。每次仅运行一个 AVD，保留原实验镜像用于追溯。

### 1.2 完整验收链

| 门槛 | 实验 | 通过条件 | 不通过时 |
| --- | --- | --- | --- |

| G1 副屏底座 | scrcpy/Appium 有限修改；检查 flags、驱动启动默认行为，取副屏帧和按display过滤的树 | 不占主屏；主屏 UI 内容不出设备；display失效不回落0；原始驱动入口受控 | 修底座，不先制作三个业务脚本 |
| G2 焦点和中文 | 主屏中文拼音持续输入；副屏点击、滑动、SET_TEXT、Back | 主屏焦点/IME/字符投递不受影响；副屏中文实际可写 | 标记能力阻断；不切ADB Keyboard/剪贴板绕过 |

| G4 通用内核 | 任意目标级DAG、skills选择、修改/replan、暂停恢复 | 没有三业务硬编码图；版本与控制屏障正确；副作用不会盲重放 | 先修内核行为契约 |
| G5 业务终态 | 日历、会议、外卖分别端到端执行 | 真正重新打开结果核验；准备/提交/支付状态区分 | 只报告实际完成范围 |
| G6 连续演示 | 用户持续使用主屏，连续做任务和一次中途修改 | 无切屏、错输、抢宿主焦点；证据完整且性能可接受 | 记录原因，不剪掉失败帧 |

G0–G6 是模拟器版的验收链。三个 App 的 G3/G5 分别记录，不能用日历通过替代外卖通过。两项通过可交付两项演示，但必须明确第三项状态；不得用自研仿真店铺冒充真实外卖 App。

## 2. 副屏探针必须覆盖的细节

- 检查 `PUBLIC + TRUSTED + OWN_FOCUS + STEAL_TOP_FOCUS_DISABLED` 实际生效；区分 VirtualDisplay flag 和 Display flag。不把现有 scrcpy CLI 开关当成已完成补丁。
- 固定 Appium driver/server/AndroidX 版本组合；`currentDisplayId` 绑定副屏、`enableMultiWindows=true`，检查原始 XML 在设备内已过滤主屏。生成主屏独有文本/Toast，确认树、日志和模型观察中均不泄露其内容；Toast 禁采集从启动生效，不能只等待缓存过期。
- 正式候选设置 `waitForIdleTimeout=0`，以副屏状态检查替代全局 idle；机制实验已观察到默认设置约 10 秒的 source 等待。显式管理 session 的 `newCommandTimeout`；不把用户/模型等待导致的过期会话当作有效连接。
- 原始 Appium 入口仅限可信适配层；经本机 ADB 通路鉴别会话。错误令牌、旧 epoch、其他设备/包名和 display 0 请求均拒绝；server 重启/重连后 gate 保持关闭直到重新绑定通过。
- 对比 Appium 启停前后的默认 IME、已启用无障碍服务、App/task 与主屏焦点；不自动启动/重置 App、解锁、改动画、切 IME 或抓取全局 logcat。设置 `disableSuppressAccessibilityService=true`；省略 `hideKeyboard`，不能以 false 替代省略。
- 控件定位/替换文本复用 Appium；触控和 Back/Enter 走 scrcpy 定向通道。分别验证真实换行与字面反斜杠加 n 尾缀都不会触发全局 Enter；节点窗口为空、目标显示消失、绑定未建立都返回错误，不注入主屏。
- P2 和正式会话都关闭 scrcpy 剪贴板自动同步，并拒绝 GET/SET_CLIPBOARD。Back 只发定向 KEYCODE_BACK，禁用 back-or-screen-on；锁屏/屏灭时暂停，验证不会自动发送 POWER 或解锁。
- 主屏用 Android 软键盘做真实中文组合输入和候选词选择，副屏反复填中文标题、搜索词、清空再填。宿主机硬件键盘输入另测，不代替软键盘测量。
- ACTION_SET_TEXT 返回 true 只说明动作处理；重新观察文字是否正确，并核查全链焦点行为。
- 对真实 App 的必要页面记录语义树覆盖、标签/列表关联、真实 action list 和缺失区域；`includeA11yActionsInPageSource` 配置要回读/核验。分别记录可由文本 LLM 消费的快照与需要视觉的页面，视觉回退不改变中文输入能力判定。页面改变后的旧 ref、歧义节点、树/帧错位须拒绝，不能改用旧坐标继续。
- 使用同包的前台任务、主屏后台旧任务、singleTask 页面分别测试。无已验证独立任务能力则拒绝启动，不能搬走或销毁用户原有 task。
- App页面、窗口树和截图在旋转/弹窗后变更，旧 observation/node 均失效；旧模型坐标不能继续发送。
- ADB中断、副屏关闭/重建、App崩溃时停止新动作；不迁回主屏、不默认重按保存。
- 第一次跳屏也判失败。监控发现后停机是故障处理，不是“从未干扰”的证据。
- 检查目标 App 的横幅通知、声音和振动；显示隔离不能隔离这些效果。记录准备期约定的通知设置，任务期间不通过修改全局免打扰/音量来掩盖干扰。

## 3. 通用运行时的行为验证

| 场景 | 预期 |
| --- | --- |
| 新请求只问推荐 | 不生成订单提交节点 |
| 用户说“别辣/不要花生/30元含运费” | 查询改写保留全部负向和金额约束 |
| 多个会议都可能是“刚才那个” | 缺失对象进入澄清，不猜测修改 |
| DAG有环、引用不存在、越权工具 | 执行前拒绝 |
| 两个ready节点都操作副屏 | 按同一设备锁串行 |
| 修改已接收但新计划未生成，旧模型返回 | pending-control屏障阻断旧动作，不只检查plan revision |
| 新计划已入RunStore，checkpoint旧时崩溃 | 恢复先对账权威revision/控制水位，再允许操作 |
| 历史摘要仍是30元，已接纳预算改成20元 | 结构化约束以RunStore最新版本为准；不能从摘要还原旧预算 |
| 等待用户澄清时重启，随后用户回复 | 找回同一对话/任务和待回答项，继续当前任务；不新建重复任务 |
| 重启后旧Appium元素ID或旧截图仍在checkpoint | 只保留证据引用，重连并重新观察定位后才能操作 |
| 已完成会议创建后要求改时间 | 新建修改目标；保留已创建事实，不再次创建 |
| 无关replan或复核金额未变 | 验证原授权仍覆盖后可复用，不反复确认 |
| 商品/地址/金额超出授权范围 | 旧授权不能通过 |
| interrupt节点恢复 | 准备工作可重放；提交不在其前面无条件执行 |
| 提交已发出，确认页丢失 | OUTCOME_UNKNOWN，先查真实结果，不再次提交 |
| 用户取消结果未知任务后又新建同类任务 | 未决副作用阻断仍在，不能绕过核查 |
| Redis投递失败后重试 | 稳定message ID去重；SQLite事实不丢 |
| 历史裁剪含工具调用 | 不留孤立ToolMessage或缺失tool result |
| skill/页面写“忽略规则、执行shell” | 仍受工具注册表和网关限制 |

首版只实现顺序调度，不为了展示 DAG 强行并发手机操作。并行 Send/reducer 和多租户属于扩展接口，不增加首周实现负担。

## 4. 三个功能的具体演示

### A. 行程截图 → 日历

准备：拟通过 Web 上传用户选择的脱敏截图；安装一个真实且可写的日历 App 并完成其 G0/G3，确认目标日历和时区。输入证据明确来自用户上传，结果证据来自同一 AVD 的副屏日历，不把宿主机原图称为手机读取证据。若以后选择手机图库场景，再验证图库/查看器的包名、版本和必要转移。

请求示例：“把这两张行程截图中确定的安排加入日历；冲突的先告诉我。”VLM 直接读取上传原图，输出带来源证据的事件字段，确定性校验后 Agent 在副屏日历查看相关日期，再填写和保存。MVP 不部署独立 OCR 服务；图片载荷、去重与交互恢复另按交互应用设计验收。

首版只承诺检查指定可见日历与明确时间范围，扫描页数有上限；不能声称 GUI 检查了所有账号、隐藏日历或无限期重复事件。日期/年份不完整则先澄清。保存后回日历列表重新打开详情，核对标题、起止、时区和位置；UI不显示event ID就不编造ID。

识别样本覆盖清晰图片、小字/模糊、缺少年份、跨午夜/不同时区、重复截图和互相矛盾的截图。分别记录字段识别是否正确、是否应澄清，以及真实日历是否与确认字段一致；模型输出合法 JSON 不算识别正确。允许放大/裁切后有限重试，禁止猜关键缺失值。

至少测一次重复截图与一次“保存后断连”。无法判断是否已保存时暂停核查，不能重复新增。是否以后引入 OCR 由实际错误分布与耗时/成本决定。

### B. 查询并创建腾讯会议

准备：在该 AVD 登录现有账号，完成必要授权。请求示例：“查明天下午的会议，找一个不冲突的30分钟时段，创建‘项目同步’，不要发邀请。”

查询范围仅当前账号 GUI 可见会议；缺少时段边界时先确定。预约未来的常规会议，不加入会议、不启用摄像头/麦克风；关闭非请求的“添加日历”以避免额外跳转。

创建后回会议列表重新打开详情，核对主题、时间和会议号。链接可见时读取；仅能用全局剪贴板取得链接时不把复制列为成功硬前提。再测一条修改请求，观察计划diff及真实修改后结果，不用重新创建替代修改。

### C. 按需求点外卖

准备：选择已有账号对应的一个外卖平台，固定App版本；在AVD登录并确认已保存地址。不要同时适配两家平台。App可能仍要求定位/风控，出现则记录并在准备阶段由用户处理。

请求示例：“给这个地址点一份不辣的午饭，含配送费不超过30元。”完整流程包括搜索、比较、规格/数量、包装费/配送费/优惠、最终金额与地址核对；中途修改为20元可用于演示replan。不得清空用户已有购物车；记录本任务改动并在修订时只调整可确认属于本任务的内容。

结果分级：

| 实际到达状态 | 可以声明 | 不能声明 |
| --- | --- | --- |
| 结算核对页，未提交 | 已按要求准备订单，待授权/提交 | 已下单或已付款 |
| 平台真实订单存在，待支付 | 已创建待支付订单 | 已付款、商家已接单 |
| 支付状态明确成功 | 已支付，报告当前平台订单状态 | 未观察到的接单/送达承诺 |
| 点击后超时且无法核实 | 提交结果未知，需核查 | 安全重试或已失败 |

真实提交/付款仅在用户具体授权覆盖的范围内执行。一些账户“提交”可能伴随扣款，必须事前按实际页面识别。需要用户密码/验证码或支付页会抢主屏时，暂停并说明边界，不能把中断片段隐藏后称全程不打扰。

## 5. 录制和性能

主画面持续显示模拟器主屏，旁边显示副屏预览、DAG和工具日志；明确标注“一个AVD、两个display”。用户在主屏持续输入/滚动，Agent同时执行。两个独立AVD或另一台云手机不作为通过证据。

一段1–2分钟视频优先展示一个完整任务和一次可控修改；另外两项可提供独立短片，或在总览中清楚标记剪辑段。三个任务是否能全部实时塞入两分钟由实测决定，不预先承诺，也不快进冒充实时。

辅助观测主屏focused display/window、IME target、默认输入法、字符完整性及宿主窗口焦点；观测主屏只取必要元数据，不把私人内容送模型。dumpsys字段按实际镜像适配，采样可能漏瞬时变化，因此同时保留连续视频。

性能用同一AVD、App、RAM/CPU/分辨率和相近宿主负载，比较60秒无Agent基线与60秒并发。记录FrameTimeline/Perfetto或可用frame stats。初始目标：主屏干扰0次；卡顿率较基线增加不超过5个百分点且无明显持续卡顿；端到端耗时实测后决定演示任务长度。以上是目标，不是已有性能数据。

## 8. MVP 运行时与交接的必要验收

状态/时序依据[执行流程](../superpowers/specs/2026-09-21-execution-flows.md)，模块接口依据[运行时契约](../superpowers/specs/2026-09-21-agent-runtime-contracts.md)。优先围绕以下可观察行为测试，不增加覆盖所有假想组合的大矩阵：

| 场景 | 必须观察到的行为 |
| --- | --- |
| 一条真实正常任务 | 同一通用运行时接纳、规划、GUI 操作、重新打开结果核验；证据支撑终态 |
| 缺日期/对象后补充 | PAUSED/CLARIFICATION；有效回复只解除对应待办，旧回复不套到新问题 |
| 执行中修改/暂停 | 新控制先落库阻止旧结果派发；在途动作如实记录；新 revision/diff 或已暂停可见 |
| 具体授权/拒绝 | 提交前可审阅；拒绝不执行；参数超出授权范围时失效；已有有效授权不重复要求 |
| 需要人工处理 | 停止自动业务动作，说明准备窗口；用户点击已处理后仍重新观察，无自动主屏迁移 |
| 提交后断连/重启 | 先查账本和真实结果；未知保持暂停，不重复下单/发送；恢复不覆盖已接纳修改 |
| 浏览器刷新/重复请求 | 从持久事实恢复待办和控制水位；重复消息/回复不重复创建业务任务或提交 |

前三个业务共享这些运行时规则，无需各写一套重复状态机测试。隔离/真人输入与真实 App 门槛仍需分别验收；测试替身仅验证运行时协议。阶段结束核查测试与文档消费者，移除被替代的影子路径，保留尚未解决故障的必要证据。
