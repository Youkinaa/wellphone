# 可行性验证、七天节奏与演示

日期：2026-09-21。**以下全部是待执行的验收计划，没有已通过的设备实验。** 本轮只交付设计，不安装大型工具链、不调用模型或操作手机数据。

## 1. 验证顺序

按用户确认范围，以一个 Android 模拟器实例完成开发与演示，真机可选。先证明操作系统通路和真实读写，再接模型。模型输出正确不能补救屏幕争用；模拟器版通过后只声明模拟器支持，不扩大为真机能力。

| 门槛 | 要回答的问题 | 最小实验 | 通过条件 | 不通过时 |
| --- | --- | --- | --- | --- |
| G0 环境 | 能否开发、连接并验证模型能力？ | 安装 SDK/Platform Tools；启动一个 API 34/35 AVD；找到可写日历；用非敏感样本探测模型 | ADB 设备确定；APK 可装；存在可读写日历；图片/JSON 或 OCR 替代链路可用 | 修正工具链/模型适配；不绕过环境问题 |
| G1 无界面入口 | 主人在打字时能冷调用 Provider 吗？ | 正常结束 Companion 进程后，在别的 App 打字；从电脑调用版本/来源读取 | 无 Activity、通知、权限弹窗；原始 caller UID 符合预期；流读取成功 | 查权限/进程机制；不以打开主屏 Companion 绕过 |
| G2 真实落地 | 能写手机日历并可靠恢复吗？ | 在选定日历新增一条测试事件并重读；重复请求、断连、写入后进程回收 | 字段正确；相同 operation 不重复；超时恢复能解释已发生写入 | 先修协议、状态和去重，不接模型掩盖失败 |
| G3 有用任务 | 模型能完成实际图片任务吗？ | 3–5 张图包含重复、跨日、缺失字段与冲突 | 明确条目写入；不明确/冲突条目按规则跳过；报告与手机读回一致 | 缩小输入规模或改 OCR/模型，公开局限 |
| G4 同实例并发 | 用户持续操作这个模拟器时是否仍成立？ | 同一 AVD 前台持续中文输入/滚动，同时连续完成 3 次完整任务 | 0 次 Agent 引发切屏/IME 切换/字符错投；宿主机窗口不抢焦点；任务读回与性能达标 | 记录镜像/宿主机配置和失败原因；修复后重测 |
| G5 副屏扩展 | GUI 能否在同机隔离运行？ | patched scrcpy + 定向触摸/ASCII + 主屏中文输入 | 所有动作绑定副屏；主屏焦点与 IME 不受影响；目标 App 终态有效 | 不进入首版承诺，保留实验结论 |
| G6 真机补验 | 模拟器结果能否迁移到该手机？ | 有设备时重跑 G1–G4；若启用 GUI 则加 G5 | 记录型号/ROM和通过能力 | 无设备则不执行，不阻塞模拟器版交付 |

G0–G4 是首版完成条件；G5/G6 是可选实验。准备日历若需要安装独立日历 App，应明确其作用是提供可见验收界面，不把 Companion 自己的列表当作系统日历结果。

## 2. G1 的关键细节

- 首次安装后用户主动打开 Companion，选择图片并复制到本地，授予日历读写权限，选择日历及允许的任务范围。
- 使用正常进程结束/系统回收模拟冷启动；另设 force-stop 测试，不能用 force-stop 的 stopped 状态冒充普通回收。必要时要求用户在正式任务前重新打开一次，但任务期间不能拉前台。
- Provider `onCreate()` 保持很短，模型不在手机运行，图片不通过 Binder 大 Bundle 传输。
- 记录 Binder 原始 UID，验证鉴权发生在 `ContentProvider.clearCallingIdentity()` 之前；在设备集成验证中从一个未授权普通 App 调用，必须失败。
- 检查 `call`、query、文件读取和路径遍历等入口；越界日历 ID、任意 URI、未知 method 一律拒绝。
- 电脑固定 serial 和 user；连接两个设备时不得“取第一台”。ADB 断连必须失败，不自动改连其他模拟器或真机。

## 3. 可靠性与真实结果

| 场景 | 预期行为 |
| --- | --- |
| 两张截图是同一张车票 | 只创建一个候选事件，保留两个来源引用 |
| 同一 job/plan 请求发两次 | 返回同一批 event ID，不重复新增 |
| 同一 job 携带不同 plan | 拒绝，要求新的明确任务 |
| 结束时间早于开始时间、缺少年份 | 标记待确认，不自动猜测写入 |
| 跨时区/跨日行程 | 保留带时区的真实时刻，并在目标时区核对展示 |
| 与重复日程重叠 | 查询实例后发现冲突，按首版默认规则跳过 |
| 同批两个候选互相冲突 | 均标记待处理，不悄悄选择一个新增 |
| 其他未选日历有事件 | 首版不检查；界面与报告明确冲突检查仅覆盖已选日历 |
| 检查冲突后用户新建日程 | 提交前重查；提交后发现的新冲突也必须报告 |
| 日历写入已成功，回执持久化前崩溃 | 按稳定来源标记找回真实记录；歧义则停止，不能盲目再插 |
| 提交结果未知，来源标记被编辑而查不到 | `NEEDS_REVIEW`，查无记录不能当作安全重插依据 |
| 用户修改 Agent 刚创建的事件 | 保留用户修改，结果标记差异，不覆盖 |
| 权限撤回/日历删除/资料不可读 | 结构化失败；不启动授权界面 |
| 模型输出越权工具或图片内指令 | 拒绝执行，不扩大资料或日历范围 |

终态核验比较：目标日历、标题、起止时间、时区、来源标记、event ID 和报告哈希。验证器重新查系统日历，不只读取自己的成功日志。最终人工在手机日历中确认一次，避免“只证明自研程序认为自己成功”。

多事件批次中部分成功时，显示“已完成 X 项，Y 项待处理”，不能显示无条件成功。测试必须覆盖提交之后超时，不能只测试提交前的断网。

## 4. 不打扰的观测方法

**连续录屏是主要证据**：同时显示模拟器主屏和 Agent 被动日志面板；用户持续滚动、输入中文并选择候选词。面板实时显示阶段、Android 端操作时间和验证结果，不自动激活窗口。画面标明“单 AVD 模拟器演示”。不能剪掉权限框、停顿或短暂切屏；不是两个 AVD 各跑一边。有真机后可补手机与电脑同框实拍。

辅助记录主屏前台窗口、focused display、IME target 和输入法标识。`dumpsys` 的字段随 ROM 变化，先保存原始样本再确定解析；采样可能漏掉瞬时切换，因此不能替代录像。审计主线没有调用启动 Activity、全局输入或切 IME 的命令。

性能实验使用相同 AVD、相同前台 App 和相近负载：先采 60 秒无 Agent 基线，再采 60 秒并发任务。固定宿主机负载、AVD RAM/CPU/分辨率与硬件加速配置；若可用，记录 FrameTimeline/Perfetto 或前台 App frame stats。较重的性能采集与正式演示分开，结果只留本地并脱敏发布，不把模拟器帧率外推为真机性能。

初步预算（需实测后调整并写明）：

- 3–5 张小图的端到端任务以 90 秒内为目标，正式录制前连续 3 次达成；不是当前性能声明。
- 新增主屏焦点/输入法干扰事件必须为 0；任何一次可归因干扰都判不通过。
- 主屏卡顿率较基线增加不超过 5 个百分点，且无 Agent 引发的持续可见卡顿；同步记录温度、刷新率和网络条件以解释数据。
- 稳态控制调用以 2 秒内为目标，图片用流式传输，业务请求并发数为 1；首次冷启动单列测量。

## 5. 可选副屏实验

只在主线稳定后进行，参考[副屏资料 R6–R10](../research/2026-09-21-platform-research.md)。

1. 固定 scrcpy v4.1 与 Android API 34/35；小改 server 加入正确的 `VIRTUAL_DISPLAY_FLAG_STEAL_TOP_FOCUS_DISABLED`。
2. 检查 `TRUSTED + OWN_FOCUS + STEAL_TOP_FOCUS_DISABLED` 实际生效；副屏采用 IME hide，关闭音频/剪贴板同步和系统装饰。仅这些 CLI 开关不足以替代 flag 修改。
3. 模拟器主屏启用 Android 软键盘并实际进行中文组合输入，副屏执行定向点击/滑动/ASCII 输入；检查主屏 top focus、IME target 和字符投递。宿主机硬件键盘输入另测；二者都不能当作真机软键盘已通过的证据。
4. 目标 App 分别验证首次启动、已有 task、外链、权限弹窗、Back、崩溃、USB 断连和副屏销毁。任何任务回到主屏都判失败。
5. 中文仅在副屏节点可正确定位且支持无 IME 设置时纳入；失败时缩小兼容范围，不能偷偷启用全局 ADB Keyboard。

## 7. 1–2 分钟演示脚本

准备阶段：在一个 AVD 内安装、授权、选择已本地化的资料、选日历；固定本机 ADB serial。素材可脱敏，但任务内容必须在运行时处理，不提前写结果。若测试日历已有记录，则事先清楚说明，避免混淆。任务入口提交后由用户回到模拟器窗口；Agent 后续不改变宿主机焦点。

| 时间 | 用户操作同一模拟器 | Agent / 电脑 | 证明什么 |
| --- | --- | --- | --- |
| 0–10 秒 | 打开聊天草稿或便笺，开始中文输入 | 输入新任务，显示唯一 job ID、已连设备和目标资料 | 本次任务现在才开始 |
| 10–70 秒 | 持续输入、候选词选择、切换信息流滚动 | 读取 Android 资料、提取、查冲突、提交日历 | 人与 Agent 在同一 Android 实例时间重叠 |
| 70–100 秒 | 继续正常操作 | 显示读回 event ID、已完成/跳过项和手机报告 | 有真实落地结果，不只是文字回复 |
| 100–120 秒 | 用户主动打开该模拟器内日历，核对新事件 | 展示来源对应关系和冲突处理 | Android 中实际可见并可使用的结果 |

时间是录制目标；若实测需要更多时间，减少首轮图片数量，不用加速剪辑伪装实时完成。预授权时间和后续查看结果不能算作“全程用户未触碰 Agent 界面”的虚假证据。
